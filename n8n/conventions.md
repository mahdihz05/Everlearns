# n8n Conventions

This document outlines the conventions for n8n workflows within the Content App V2 ecosystem.

## 1. Naming
- **Workflows:** Use lowercase, kebab-case naming for all workflow names (e.g., `ai-text-orchestration`, `publishing-immediate`).
- **Nodes:** Name nodes descriptively using Title Case to clearly identify their purpose (e.g., `Send Webhook to Django`, `Process AI Text`).

## 2. Folders and Structure
- Store all core orchestrations directly in `n8n/workflows/`.
- Reusable sub-workflows (called via "Execute Workflow" nodes) should be kept in the same directory but must be clearly identifiable by a `subflow-` or `agent-tool-` prefix (e.g., `agent-tools-text.json`).

## 3. Subflows
- Complex logic should be modularized into subflows.
- Main workflows must orchestrate the flow by calling specific subflows rather than including everything in one giant canvas.

## 4. Environment Variables
- All secrets, API keys, endpoints, and credentials MUST be configured as Environment Variables or standard n8n credentials.
- NEVER hardcode secrets in the workflow files.
- Refer to `n8n/.env.example` for required variables.

## 5. Input and Output Schemas
- Input to workflows must be structured JSON.
- Core metadata must include `executionId` (or `correlationId`) to track processes back to Django.
- Output back to Django must include structured status codes, success flags, and well-formed payload data.

## 6. Versioning
- Workflows are version-controlled in git. Update the `id` or name in the workflow metadata only if branching a completely new version. Keep track of modifications through git commits.

## 7. Correlation IDs
- `correlationId` (typically generated by Django) MUST be passed through the entire workflow and returned in all status updates and webhook responses to Django.

## 8. Error and Status Format
- If a node fails, it must route to an error handler subflow or node.
- Errors must be reported back to Django with:
  - `status`: `"failed"`
  - `correlationId`: `<id>`
  - `error_message`: `<string>`
  - `step`: `<string>`
